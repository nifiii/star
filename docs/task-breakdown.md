# 任务拆解

## 1. 背景

本期采用 Lightweight，按可独立验收的垂直切片拆分，避免先做大范围重构。

## 2. 目标

每个任务都能对应业务规则和验收用例，完成后可回归现有页面。

## 3. 方案

2026-10-22 当前页面优化任务以 `responsive-redesign.md` 的 UI-01~03 为准。以下 T-001~007 保留为早期 MVP 规划，不能理解为后端契约、安全迁移或时间过滤已经全部完成。此次 Scope 为 App、ConfigPanel、前端查询服务、比分纯函数、入口和样式，不修改采集脚本。

| 任务 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| T-001 | 固化姓名、同名、双打和数据范围规则 | 用户确认 BR-001~005 | 规则记录完成 |
| T-002 | 为 `/api/matches` 增加结构化状态和错误码，保留旧字段 | T-001 | AC-004~007 |
| T-003 | 将采集凭证改为环境变量必填，移除默认密码，增加启动校验 | 无 | AC-010 |
| T-004 | 修正比分展示与多局/缺失比分状态 | T-001,T-002 | AC-002,003,007 |
| T-005 | 补齐查询缓存键、错误重试和部分成功展示 | T-002 | AC-005,006,009 |
| T-006 | 使用脱敏 fixture 做前端和接口回归 | T-002~005 | AC-001~010 |
| T-007 | 运行构建、窄屏/桌面手工检查和上线检查单 | T-006 | 视觉与发布验证 |

### Outcome

家长/教练可以可靠查询运动员比赛比分和成绩，并能区分无记录、数据不完整和系统故障。

### Inputs

本目录 PRD、用户确认的 BR 规则、API 契约、验收用例和脱敏样本。

### Scope

`App.tsx`、`components/ConfigPanel.tsx`、`services/huaTiHuiService.ts`、`types.ts`、`scripts/getToken.js` 及相关测试/文档。

### Non-goals

排行榜增强、Gemini AI、账号体系、多租户、上游接口替换、容器拆分。

### Acceptance

`docs/acceptance-tests.md` 全部通过，`npm run build` 通过，桌面/移动端关键状态完成手工检查。

### Freedom

可在既有 React/Express/Tailwind 技术栈内选择最小实现；不得引入新状态管理库或为本期需求重构目录。

### Dependencies

T-001 是 T-002/T-004 的前置；T-002 是 T-005/T-006 的前置。

## 4. 风险

- 若用户确认的规则与当前上游字段冲突，必须先更新所有文档再编码。
- 凭证迁移涉及生产配置，必须准备回滚用的环境变量配置，不得把旧密码重新提交到 Git。
