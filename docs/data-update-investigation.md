# 数据更新问题定位记录

## 1. 背景

用户反馈远程 `star` 服务存在部分数据无法更新。本记录只保留不含凭证的证据和根因边界。

## 2. 目标

区分“采集任务未运行、上游请求失败、增量跳过、写盘失败、查询读到旧缓存”五类原因，确认前不做猜测性修复。

## 3. 方案与当前证据

### 已确认的本地代码风险

- `fetchGameList()` 对上游异常返回空数组；`runDailyUpdate()` 将空数组视为正常结束并返回成功，任务可能静默不更新。
- 赛事列表请求固定 `page_size=200`，而本次接口报告总数 1392；当前逻辑只处理第一页，后续页的新增赛事不会进入本次同步。
- 增量逻辑只按 `raceId` 判断是否已有排名和比分；已有比赛不会重新抓取，后续补录比分或更正比分不会被刷新。
- 两个 JSON 文件使用直接 `writeFileSync` 覆盖写入，没有临时文件替换；进程中断可能留下半写文件。
- Docker 启动命令把 Node 采集进程放在后台、Nginx 放在前台；Node 进程退出时容器仍可能显示为运行中。

### 已确认的远程证据

- SSH 别名 `star` 指向 `43.165.184.101:22`，当前登录用户为 `root`。
- `hth-dashboard` 使用镜像 `hth-dashboard:v1.1.8`，容器自 `2026-01-13 05:46:49` 持续运行，`restartCount=0`。
- 容器内 `/app/scripts/getToken.js` 进程仍在运行，启动命令为 `npm run get-token`；Node 进程未退出。
- 05:00 定时任务持续触发。日志显示 `2026-09-06 05:00` 最后一次成功写入（新增排名 24、比分 220）；`2026-09-09` 起每天 05:00 均打印“登录失败”。
- 数据文件最后写入时间为 `2026-09-06 05:00:53`（比分）和 `2026-09-06 05:00:52`（排名）；`auth_config.json` 最后更新时间为 `2026-09-08 09:47:20`。
- 容器和宿主机解析华体汇域名正常：`user.ymq.me`/`applyv3.ymq.me -> 114.55.199.31`，`race.ymq.me -> 47.98.65.199`。
- 从容器和宿主机到上述地址的 TCP/443 均在 8 秒内超时；同一宿主机访问 `www.baidu.com` 返回 200，且到 `8.8.8.8:443`、`1.1.1.1:443` 可建立连接。
- 宿主机 `iptables` 的 `OUTPUT` 策略为 `ACCEPT`，`firewalld` 未运行；本机工作站访问同一华体汇地址返回 200。

### 本机对照测试（2026-10-22）

- Codex 工作站解析三个域名正常，TCP/443 均可建立，HTTPS 返回：`user.ymq.me=200`、`applyv3.ymq.me=404`（根路径无资源，但连接正常）、`race.ymq.me=200`。
- 使用项目相同的赛事列表请求但不带真实账号，`applyv3` 返回业务 `code=1`，数据总数为 1392 条；这只验证网络和接口可用，不验证账号登录。
- 使用已有赛事 `raceId=37980` 做只读接口探测，返回 31 个项目、9 个组别、1 条比分记录和 24 条排名记录。
- 空账号登录请求返回 HTTP 200、业务 `code=-1`“参数不合法”，说明登录接口本身可达；未使用真实账号进行登录尝试。

### 增量同步执行记录（2026-10-22）

- 使用 `star` 容器注入的账号在本机登录成功（HTTP 200、业务 `code=1`），凭证未写入仓库或同步文件。
- 以 `star` 原有数据为基线执行一次采集，保留原有 114,540 条比分和 37,325 条排名，新增 10,621 条比分和 2,667 条排名。
- 同步前备份目录：`/usr/local/hth-data/backups/20261022-1036-incremental/`。
- 上传文件先写入临时文件，远程 JSON 校验通过且 SHA-256 与本地生成文件一致后，再原子替换两个数据文件；未替换 `auth_config.json`。
- 容器重启后内存加载结果为排名 39,992 条、比分 125,161 条，API `updatedAt` 为 `2026-10-22 10:44:23`；容器保持运行。

### 历史比分与排名刷新记录（2026-10-22）

- 使用远程账号在本机重新请求 300 个赛事；原有 264 个赛事 ID 全部覆盖，返回空比分的赛事保留原记录。
- 刷新后比分 128,409 条、排名 43,228 条；比分 `0:0` 从旧数据的 41,293 条降至 3,986 条，非 `0:0` 比分为 124,423 条。
- 刷新结果与远程临时文件 SHA-256 一致后才替换；本轮备份目录：`/usr/local/hth-data/backups/20261022-1215-refresh/`。
- 容器重启后日志确认内存加载为排名 43,228 条、比分 128,409 条，容器保持运行。

### 根因结论

状态：`已确认`。

直接根因是 `star` 公网出口（源地址 `43.165.184.101`）到华体汇三个目标地址的 TCP/443 连接不可达/被丢弃。故障发生在 HTTP 登录请求建立之前，因此不是华体汇账号密码校验、赛事筛选、排名解析或 Docker 进程退出导致。

当前证据可以排除容器网络独有问题和宿主机默认出站防火墙，但还不能在“云安全组/出口 ACL/运营商路径”和“华体汇侧按源 IP 丢弃”之间进一步定责。需要云厂商出站策略与华体汇服务方确认，或从同一公网出口的其他实例做对照测试。

代码将 `fetch()` 异常全部吞掉，只返回 `false`/空数组，最终只显示“登录失败”，导致网络故障表现为静默旧数据。这是可修复的观测性缺陷，但不会改变当前网络根因。

### 网络恢复后的复核

```bash
curl -k -I --connect-timeout 8 https://user.ymq.me
curl -k -I --connect-timeout 8 https://applyv3.ymq.me
curl -k -I --connect-timeout 8 https://race.ymq.me
docker logs --since 1h hth-dashboard 2>&1 | grep -E '登录成功|登录失败|获取赛事列表|更新成功|Scheduled crash'
docker exec hth-dashboard find /app/data -maxdepth 1 -type f -printf '%TY-%Tm-%Td %TH:%TM:%TS %s %f\n'
```

上述命令不得输出账号、密码、token、原始请求体或完整上游响应。

## 4. 风险

- 网络出口未恢复前不能通过重启容器解决问题；重启不会改变 TCP 路由或上游封禁状态。
- 修复前应保留当前数据文件和容器配置，避免用空响应覆盖最后一份有效数据。
- 即使发现容器存活，也不能据此证明 Node 采集进程存活；必须同时检查进程和最近日志。
- 网络恢复后还需单独处理增量逻辑：当前按 `raceId` 跳过已有赛事，补录或更正的比分不会自动刷新。
