# 页面状态

## 1. 背景

比赛查询需要同时表达数据结果和数据源状态，不能只依赖一张空表。

## 2. 目标

所有用户可见状态都有明确文案、下一步操作和可验证条件。

## 3. 方案

| 状态 | 触发条件 | 用户看到的内容 | 操作 |
|---|---|---|---|
| 首次进入 | 尚未提交 | 姓名查询引导 / 成绩筛选引导 | 填写条件并提交 |
| 正常 | 返回至少一条记录 | 条件快照、统计、完整赛事/组合、分页 | 查询、导出全部结果 |
| 加载 | 请求未完成 | 进度、禁用表单和切换 | 等待，20 秒超时后可重试 |
| 空数据 | 请求成功但 0 条 | 当前筛选条件、可能原因 | 修改姓名/筛选、重试 |
| 错误 | HTTP/网络/认证失败 | 错误类型，不泄露凭证 | 重试、联系运维 |
| 无权限 | 查询 API 返回 401/403 | 查询无权限提示 | 联系管理员 |
| 校验失败 | 姓名为空或仅空格 | 输入框错误提示 | 修正输入 |
| 字段缺失 | 有记录但时间、轮次或比分缺失 | 保留记录；时间/轮次待定；结果待确认 | 查看现有记录 |
| 成功 | 查询结束且数据展示完成 | 成功条数和统计 | 继续筛选 |
| 失败重试 | 重试仍失败 | 保留上次失败原因和请求时间 | 再试或调整条件 |

## 4. 风险

- 前端不能从查询 HTTP 200 反推上游采集成功；没有单独的系统运行提示面板。
