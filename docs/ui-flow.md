# 用户流程

## 1. 背景

Gemini 与系统状态面板已移除。2026-10-22 页面优化保留比赛战绩和赛事成绩两个入口，改用通栏布局。

## 2. 目标

让家长或教练从输入姓名到阅读比赛记录的路径不超过一次查询提交，并能在失败时重试或调整筛选。

## 3. 方案

```text
进入查询页
  -> 输入姓名
  -> 可选选择性别/城市/赛事关键字
  -> 提交查询
  -> 加载与进度
  -> 有结果：统计卡片 + 比赛列表
  -> 无结果：说明可能原因 + 调整筛选/重试
  -> 接口失败：显示失败原因 + 重试
```

页面/视图：

- `PLAYER_HISTORY`：运动员比赛记录查询，PC 表格、手机卡片。
- `DASHBOARD_RANKS`：既有赛事排名查询，点击运动员跳至战绩；顶部导航可返回原查询结果。
- 两页共享筛选配置；各自保留已查询结果与条件快照。修改输入不会改变结果所属条件。
- 每页 20 条，翻页将焦点移到结果区域。导出包含完整查询结果。
- 查询进度和错误就地展示，无独立系统状态页。重置仅调整表单，不静默发起请求。

## 4. 风险

- 分页针对接口已经返回的记录；服务端原有排名结果上限保持不变。
- 姓名命中只表示文本匹配，结果区始终提示同名风险。
